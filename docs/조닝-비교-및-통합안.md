# 두 조닝안 비교와 통합안

**비교 대상**
- **A안** — `kpharmacy-zoning-63.json` (제가 엑셀·PDF에서 생성한 기준안, 2026-09-17)
- **B안** — `Pharmacy_Layout_Studio_Zoning_v7_1.json` (업로드하신 도면 기반 모델)

**결론 먼저.** **B안이 실무에 더 적합합니다.** A안은 치수를 역산해 만든 가설이고,
B안은 도면 치수열에서 읽은 실제 배치입니다. 통합안은 **B안을 기준(base)으로 두고
A안의 품목 분석 계층만 얹는 구조**입니다.

---

## 1. A안의 오류 — 매장 크기를 1.7배로 잡았습니다

| | A안 (제 기준안) | B안 (업로드) |
| --- | --- | --- |
| 매장 | 15,400 × 12,200mm · **56.8평** | **10,512 × 10,319mm · 32.8평** |
| 근거 | 최소 통로 1,300mm를 만족하도록 역산 | 도면 치수열 `1,502 + 7,520 + 1,490 = 10,512` |
| 모듈 폭 | 1,300mm (가정) | **925mm** (피치 = 3,390 − 2,465) |
| 곤돌라 깊이 | 900 (면당 450) | **700 (면당 350)** |
| 엔드 깊이 | 450 | **307.5** (= (2,465 − 2×925) / 2) |
| 통로 | 1,350 ~ 1,700 (역산) | **951 / 1,000 / 1,295 / 1,379 / 1,405** (실제) |
| 집기 높이 | 벽면 2,100 · 중앙 1,650 | 벽면 2,100 · **좌측 1,800 · 하단 1,500 · 중앙 1,600** |

제가 한 일은 순서가 거꾸로였습니다. **"최소 통로 1,300mm는 지켜야 한다"는 규범을 먼저 놓고
거기에 매장을 맞췄습니다.** 실제 도면의 통로는 951mm·1,000mm로 그 기준보다 좁습니다.
B안의 기록이 정확합니다.

> "원도면 951mm·1000mm 통로를 임의로 넓히지 않음. 앱 minAisle=1200은 검토 설정이며
> 법정 적합성 판정이 아님." — B안 `geometryLimits`

이 원칙이 맞습니다. 도구의 기준값에 현실을 맞추면 안 됩니다.

**부수적으로 확인된 사실.** 지난 답변에서 제가 열어 두었던 질문 —
"오른쪽 곤돌라 2대 중 G5가 위인지 아래인지" — 는 B안 도면으로 확정됩니다.
좌측열이 위에서부터 **G4 → G3 → G2 → G1**, 우측열이 **G6 → G5** 입니다.
G1이 입구에 가장 가깝고 G5는 우측 하단입니다. A안은 이 순서를 뒤집어 놓았습니다.

## 2. B안이 더 나은 다른 지점들

| 항목 | B안 | A안 |
| --- | --- | --- |
| **평면도 배경** | 원도면 PNG를 임베드해 좌표를 대조 가능 | 없음 |
| **원본 보존** | `zoning.sourceShelves` 에 315칸 × 10필드 전부 유지 (후보·공급코드·대체안·선정기준·근거수준) | 일부 필드만 |
| **안내·조건부 칸** | category 를 **비워** 3D에 상품 타일이 생기지 않게 함 | 채워 넣어 재고가 있는 것처럼 보임 |
| **단 번호** | 선반마다 `sourceTopDownShelf` + `simulatorBottomUpLevel` 양쪽 기록 | 문서 단위 플래그 하나 |
| **양면 모델링** | D면·W벽면을 180° 회전해 등판을 맞댐 | 단순 배치 |
| **냉장고** | RF1을 **315칸 외 별도**로 명시 | 보조 공간으로만 처리 |
| **한계 기록** | 가로 치수열 6mm 불일치, POS·조제실은 비례 모델임을 명시 | 없음 |

특히 **안내 70칸·조건부 70칸을 의도적으로 비워 둔 판단**은 제가 놓친 것입니다.
원안이 "안내 선반은 추가 재고 공간으로 채우지 않음"이라고 못박았는데, 제 임포트는
전 칸에 분류를 채워 3D에서 모든 선반이 상품으로 찬 것처럼 보이게 만들었습니다.

## 3. A안이 가진 것 — 품목 분석 계층

B안에 없고 A안에만 있는 것은 하나입니다. **카탈로그 2,526품목과 모듈의 연결.**

- 엑셀 `03_상품분류2526` 의 `권장 주 진열` 을 모듈 코드로 파싱해 **모듈별 배정 품목 수** 산출
- 그 수를 상설 선반 수용력과 대조해 **적재 과부하** 판정
- 미배정 520 · 냉장 156 · 면단위 미확정 144건의 분리 집계

B안은 선반마다 `representativeCandidates`(대표 후보 1~3개)를 갖지만
전체 카탈로그와의 연결이 없어 "이 모듈이 감당해야 할 품목이 몇 개인가"를 알 수 없습니다.

## 4. 통합안 = B안(기준) + A안의 분석 계층

### 4.1 구성

```
B안 (그대로 유지)                        A안에서 가져옴
─────────────────────────              ─────────────────────
좌표·치수·통로                     +     모듈별 SKU 배정 수
평면도 배경                        +     포장 형태별 페이싱 수용력
sourceShelves 315칸 원본            +     운영상태의 1급 필드화
안내·조건부의 빈 category           +     과부하·저활용 진단
양면 180° 모델링                    +     kpharmacy.zoning/1.1 교환 형식
```

**B안의 좌표·치수·통로·빈 칸은 한 글자도 바꾸지 않았습니다.**

### 4.2 산출물

| 파일 | 용도 |
| --- | --- |
| `data/kpharmacy-integrated-layout.json` | **시뮬레이터에 바로 올리는 통합안.** B안 원본 + `zoning.skuCandidates` 주입 |
| `data/kpharmacy-zoning-63.integrated.json` | 교환용 `kpharmacy.zoning/1.1` (260KB, 모듈별 수용력·적재율 포함) |
| `data/uploaded-drawing-model.json` | B안 원본 보관 |

### 4.3 도구 변경 (v7.2)

B안을 그대로 올려도 분석이 켜지도록 시뮬레이터를 고쳤습니다.

| 변경 | 내용 |
| --- | --- |
| **`zoning` 블록 하이드레이션** | `sourceShelves[].status` → 단별 운영상태, `sourceId` → 선반 ID, `productGroup`·`need`·`selectionNotes` 를 편집 필드로 승격. **B안 원본을 올려도 운영상태 색·3D 운영상태 모드·적재 진단이 동작합니다.** |
| **페이싱 기반 수용력** | 고정 14품목/선반 → **모듈 실폭 − 측판 60mm ÷ 포장별 페이싱 폭**. 실폭 925mm가 들어오면서 기존 상수는 40% 과대평가였습니다. |
| **라벨 정립** | 180° 회전 집기의 글자가 뒤집히던 문제(B안이 기록한 한계)를 도형은 두고 글자만 되돌려 해결 |
| **계획 칸 제외** | 안내·조건부 칸을 분류 완성도 분모에서 제외. B안에서 "55%만 분류됨"으로 잘못 잡히던 것을 정정 |
| **중복 지적 병합** | 같은 유형 35건이 목록을 채워 중요한 단일 지적을 밀어내던 문제 해결 |

## 6. 통합안에서의 재배분 제안

앞서 A안 기준으로 드린 제안(G2 2모듈 회수 → 더마 이관)은 **방향이 유지되지만
규모가 부족합니다.** 실측 기준으로는 다음과 같이 조정해야 합니다.

### 6.1 즉시 (집기 이동 없음)

| # | 조치 | 효과 |
| --- | --- | --- |
| 1 | **G2-U-3**(습윤·상처 세정, 11%) → G2-U-1에 통합, 모듈은 **B 잡티·톤 확장**으로 전환 | 더마 +4상설단 |
| 2 | **G2-D-2**(실리콘 겔) → G2-D-1에 통합, 모듈은 **A 피지·모공 확장**으로 전환 | 더마 +4상설단 |
| 3 | **G2-D-3**(일반·방수 밴드, 18%) 상설 4 → 2단, 2단을 조건부로 | 피부약 −2, 여력 확보 |
| 4 | **G5-D-1**(브랜드존, 10%) 상설 3 → 2단 | E축 인접 여력 |
| 5 | 과적 10개 모듈의 **조건부 → 상설** 전환 | 더마 +9상설단 |
| 6 | **L4**(구강, 18%)·**G6-U-1**(발 의약품, 25%) 상설 각 1단 축소 검토 | 여력 확보 |

①②⑤만 적용해도 더마 상설 35 → 52단, 수용 350 → 520, **충족률 41% → 60%** 입니다.

### 6.2 실측 후 (집기 변경 검토)

현재 통로는 951 / 1,000 / 1,295 / 1,379 / 1,405mm 입니다.
**관광객 캐리어 동선을 고려하면 951mm·1,000mm 구간을 넓히는 쪽이 우선**이며,
집기 증설로 수용력을 늘리는 방향은 권고하지 않습니다.
대신 **G2를 3모듈/면에서 2모듈/면으로 줄여 곤돌라 길이를 3,390 → 2,465mm로 단축**하면
좌우 통로가 각각 460mm 넓어지고, 회수한 2모듈은 G5 인접으로 옮길 수 있습니다.
이는 실측과 집기 발주 전에만 가능한 결정입니다.

### 6.3 그래도 남는 것

> 상설 138단 총 수용 **1,859품목**(1페이싱).
> 주력에 2~3페이싱을 주면 **실질 1,150~1,340품목**.
> 카탈로그 2,526품목 중 **약 46~53%만 상설 진열 가능**합니다.

A안에서 "55~60%"라고 말씀드린 수치는 과대였습니다. 실측 기준으로는 **절반 이하**입니다.
미배정 726품목(28.7%)은 여전히 누락이 아니라 산술적 귀결이며, 그 폭은 더 큽니다.
